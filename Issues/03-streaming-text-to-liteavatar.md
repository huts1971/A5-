# 文字输入流式回答接入 LiteAvatar 自动播报

类型：AFK

状态：已完成（2026-06-28）

覆盖用户故事：1、2、3、4、5、6、20、29、32、34

## What to build

保留 A5 现有文字输入、`/api/chat/stream`、回答展示和来源卡链路，同时将同一回答流的可播报文本增量提交给 avatar bridge。由 OpenAvatarChat TTS 与 LiteAvatar 尽早开始语音和数字人播放，不等待完整回答或来源卡返回。

A5 仍是唯一答案真相源；avatar service 不调用自己的 LLM、不改写答案，也不代理 A5 问答。数字人未 ready 时，本次回答继续正常显示且不排队补播。

## Acceptance criteria

- [ ] 文字提问继续调用 A5 现有流式聊天接口，并保持现有用户消息、回答和来源卡行为。
- [ ] 同一回答流被同时消费用于聊天文本展示和 avatar bridge 增量播报，不新增第二次 LLM 请求。
- [ ] avatar service 不生成、改写、总结或补充 A5 回答内容。
- [ ] 数字人在收到足够的首批文本增量后即可开始播报，无需等待完整 answer 或 sources。
- [ ] 文本流分段不会造成明显重复播报、丢字或乱序。
- [ ] 来源卡可以晚于播报开始出现，且其展示不受数字人链路阻塞。
- [ ] avatar session 未 ready 或提交失败时，问答继续完成，本次未播内容不在恢复后补播。
- [ ] 提问后左侧状态进入“思考中”，实际开始输出音视频后进入“播报中”。
- [ ] 页面不提供历史回答的播放、重新播报或音频按钮。
- [ ] A5 backend 不承担 avatar 音视频代理职责，现有公共聊天 API 行为保持兼容。
- [ ] 有行为级测试或可重复联调验证覆盖正常流式播报、avatar 不可用和来源卡晚到三种场景。
