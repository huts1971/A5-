# 业务接入

## 后端入口

`backend/app/services/agentic_runtime.py` 的 GuideCoreRuntime 负责核心配置、模型生命周期、发布清单、问答与知识重建。

`backend/app/api/chat.py` 校验用户与会话；`services/chat.py` 将知识问答交给核心，将图片、路线和位置操作交给业务服务。返回原 ChatResponse，沿用引用、TTS、SSE 和问答日志接口。

| 数据 | 适配方式 |
| --- | --- |
| ScenicSpot / SpotFact | 导出景点介绍及结构化事实 |
| KnowledgeDoc | 重新读取原文件进行结构解析 |
| MapPoint / CoreDocumentScope | 确定景区与景点过滤范围 |
| ChatSessionAccess | 校验会话归属 |
| ChatMessage.metrics_json | 保存耗时、核心 trace 和 corpus_id |

## 发布与读取

后端 `app.core_cli rebuild` 将业务实体与资料生成不可变语料，完成索引后切换发布指针。`Corpus.load` 读取指针指定的文件并校验指纹。问答前后核对数据库修订号，保证引用对应当前知识版本。

## 长期记忆

`MemoryStore` 默认使用独立 SQLite，也支持 SQLAlchemy MySQL URL。后端根据游客身份读取授权、写入任务；`MemoryWorker` 提取用户原句中的静态偏好和会话约束。

静态示例为 `walking_preference=偏好轻松步行`，动态示例为某会话的 `duration_minutes=120`。编辑携带 expected_version，入队携带授权 epoch，删除与撤回推进 epoch 并取消旧任务。

## 独立适配器

`integration.py` 另提供 LegacyRetrievalAdapter、LegacyChatAdapter 和 BackendContext，供其他宿主复用原检索及聊天 DTO。宿主提供已验证用户、会话、景区、事件 ID 和时间，管理 TTS 与数据库生命周期。

整站接口与状态字段见 [架构说明](../../../docs/architecture.md)。
